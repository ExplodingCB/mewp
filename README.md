# Mewp

A free, open-source, native **Swift / SwiftUI macOS cleaner**: junk cleanup, a disk space map,
large-file and duplicate finders, an uninstaller, and more.

Nine modules plus a menu-bar monitor, built entirely on native APIs (sysctl, Vision,
`FileManager`), with a safety database that decides what is allowed to be touched.

## Install

```sh
brew install --cask explodingcb/tap/mewp
```

That taps [`ExplodingCB/homebrew-tap`](https://github.com/ExplodingCB/homebrew-tap) and drops
`Mewp.app` into `/Applications`.

To upgrade later:

```sh
brew upgrade --cask mewp
```

Mewp used to be called CleanMyMewp. If you installed it under that name, `brew upgrade` moves
you to the `mewp` cask automatically; you'll need to grant Full Disk Access to `Mewp.app` again.

To uninstall:

```sh
brew uninstall --cask mewp
```

Prefer not to use Homebrew? Grab the `.zip` from the
[latest release](https://github.com/ExplodingCB/mewp/releases/latest),
unzip it into `/Applications`, and run:

```sh
xattr -dr com.apple.quarantine /Applications/Mewp.app
```

> The app is **ad-hoc signed** (no paid Apple Developer account), so it is not notarized.
> The Homebrew cask strips the quarantine flag for you; a manual install needs the `xattr`
> command above or macOS will refuse to open it.

### Full Disk Access

Most modules need Full Disk Access to see caches, other apps' containers, and system logs.
The app has an in-app prompt that deep-links to
**System Settings → Privacy & Security → Full Disk Access**. Because the signature is ad-hoc,
the grant is tied to the exact bundle — **re-grant it after every upgrade**.

Requirements: macOS 14 or later, Apple Silicon or Intel (the release binary is universal).

## Modules

| Module | What it does |
| --- | --- |
| **Checkup** | One-pass scan combining junk, leftovers, and system-health recommendations |
| **Cleanup** | Caches, logs, browser data, sandbox containers, package-manager junk, Trash |
| **Space Map** | Interactive bubble map of what is eating your disk |
| **Large Files** | Big files you have not touched in a long time |
| **Duplicates** | Size → 64 KB partial hash → full SHA-256 |
| **Uninstaller** | App inventory, six-month-unused filter, strict bundle-ID leftover matching |
| **Similar Images** | Local dHash prefilter plus Vision feature-print comparison |
| **Performance** | Live memory pressure, swap, CPU, and top processes |
| **Startup Items** | launchd agents and daemons, with enable/disable controls |

## Safety rules

These are non-negotiable, and there are tests that enforce them:

- **Trash-first.** Deletes go to the Trash via `FileManager.trashItem`; permanent unlink is
  opt-in. The one exception is the contents of `~/.Trash`, which cannot be trashed again.
- Everything removable is declared in `SafetyRules` with a `RiskLevel`, and **only `.safe`
  items are pre-selected**. Nothing is deleted without you checking a box.
- Forbidden roots — `/System`, `/private/var/folders`, `.lproj` stripping, lipo stripping —
  are excluded by design and covered by `testNoCategoryTargetsForbiddenRoots`.
- App bundles are never modified, because that breaks their code signatures.
- Broad root-cache deletion is intentionally absent. Only individually reviewed `/Library`
  children from the safety database are ever removed.
- Privileged maintenance uses per-action macOS administrator prompts, not a persistent
  privileged helper.

## Building from source

The Xcode project is generated by [XcodeGen](https://github.com/yonabu/XcodeGen) from
`project.yml` — **edit `project.yml`, never the `.xcodeproj`**, then regenerate.

```sh
brew install xcodegen
xcodegen generate

# Debug build
xcodebuild -project Mewp.xcodeproj -scheme Mewp \
  -configuration Debug -destination 'platform=macOS' build

# Unit tests (32 of them)
xcodebuild -project Mewp.xcodeproj -scheme Mewp \
  -configuration Debug -destination 'platform=macOS' test

# Universal release build, the way the shipped .app is produced
xcodebuild -project Mewp.xcodeproj -scheme Mewp \
  -configuration Release -destination 'platform=macOS' \
  -derivedDataPath ./build ARCHS="arm64 x86_64" ONLY_ACTIVE_ARCH=NO build
```

Requires Xcode 26. Signing is ad-hoc (`CODE_SIGN_IDENTITY: "-"`), so no Apple Developer
account is needed.

> `xcodebuild test` leaves a stale `MewpTests.xctest` inside the Debug `.app`, which
> makes the next `build` fail codesign with "bundle format unrecognized". Delete the Debug
> `Mewp.app` before rebuilding.

## Layout

```
Sources/App/       @main app, RootView sidebar navigation, Theme
Sources/Core/
  Scanner/         DirectoryScanner, TreeScanner, FileWalker
  SafetyRules/     the safety database — the single source of truth for Cleanup
  Deletion/        Deleter (trash-first, permanent override)
  Duplicates/      DuplicateFinder
  Images/          dHash + Vision similarity
  Maintenance/     administrator-prompted maintenance
  StartupItems/    launchd controls
  System/          diagnostics and the low-overhead menu-bar sampler
  Uninstaller/     app inventory and leftover matching
  Permissions/     Full Disk Access probe and deep-link
  Util/            ByteFormat, concurrentMap, FileActions, VolumeSpace
Sources/Modules/   the nine modules
Tests/             engine tests against throwaway fixture trees
```
